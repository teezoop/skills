# 向导

**向导**是一个 bash 脚本，逐步引导人类完成手动操作流程。这些流程既不便逐项手做，也不便每次重新向 AI 解释。向导打开每个 URL，明确说明点击和复制什么，收集数值并写入相应位置，例如 `.env` 或 GitHub secrets；每个阶段都确认，并展示还剩多少阶段。它可以配置第三方服务、执行一次性迁移，或让项目从一个状态切换到另一个状态。

良好的用户体验已由 [template.sh](template.sh) 解决：分阶段进度、确认关卡、跨平台打开 URL（包括 WSL）、隐藏密钥输入、幂等 `.env` 更新或插入、写入 `gh secret` / `gh variable`，以及结束摘要。**你的工作仅是确定流程范围并编写各阶段。** `STAGES` 标记上方的库代码在每个向导中都完全一致，这种一致性正是目的所在，绝不要手工修改它。

向导默认是临时的：只为运行一次而构建，保存到临时工作区或 `scripts/` 路径，任务完成后删除。只有用户希望仓库中保留可重复的配置流程时，才提交它。

## 流程

### 1. 确定流程范围

梳理人类必须完成的每个手动步骤，以及过程中要收集的每个值。先读仓库，不要毫无背景地询问：

- 配置场景：检查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置及 `.github/workflows/*`。每个 `secrets.*` / `vars.*` 引用都代表向导必须产出的值。
- 迁移或切换场景：了解当前状态、目标状态和两者之间不可逆的操作。

随后向用户展示有序阶段清单和各阶段产出的值，并确认；用户可以增加、删除或调整顺序。

**完成标准：** 每个阶段已按顺序命名；对每个收集值，都知道：(a) 人类从哪里获取；(b) 写入哪里（`.env`、GitHub secret、两者都写或哪里都不写，有些阶段只是操作）；(c) 是否为秘密值（隐藏输入）或公开值。

### 2. 映射每个阶段的操作路径

为每个阶段写出人类应走的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、填入哪个变量。例如“Dashboard → Developers → API keys → Reveal test key → 复制”。如果确实不了解当前 UI 或准确命令，明确说明，并询问用户或查看文档；绝不编造可能不存在的步骤。

**完成标准：** 每个阶段都能对应到陌生人也能照着执行的具体指引。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用每个步骤对应的 `stage` 替换示例阶段，按依赖顺序排列。使用库助手：`stage`、`say` / `step`、`open_url`、`ask` / `ask_secret`、`write_env`、`set_secret` / `set_var`、`pause` / `confirm`。将 `TOTAL_STAGES` 设为实际阶段数量。

维持模板设定的标准：先打开 URL 再询问值；所有秘密值都用 `ask_secret`；每个需持久化的值都用 `write_env`；只有 CI 实际需要的值才用 `set_secret`；任何不可逆操作前都使用 `confirm`。每个 `stage` 会清屏，只显示当前步骤，因此每阶段只处理一个聚焦任务，避免人类需要的信息滚出屏幕。不要修改标记上方的库代码。

### 4. 验证与交付

- 运行 `bash -n <script>`；如果有 `shellcheck`，也运行它。
- 运行 `chmod +x <script>`。
- 不要自己端到端运行，因为它会打开浏览器并等待人类输入。改做静态追踪：步骤 1 中的每个值都被收集并写到所指定的位置；每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用准确一致。
- 告诉用户如何运行。如果这是可重复使用的配置流程，就提交并从 README 链接它，让下一位使用者直接运行脚本，而不是再询问 AI。
