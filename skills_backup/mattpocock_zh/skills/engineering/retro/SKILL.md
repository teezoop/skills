用户请求进行**复盘**。你要为编码代理的**工作环境**提出改进建议，以提高未来运行的效果。

## 步骤

1. 调用 Skill 工具加载 `writing-for-agents`，获取写作风格指导。

2. 阅读用户指定会话的一手资料，可能需要搜索本机的会话日志。如果用户没有指定，默认复盘当前会话。

3. 从以下类别寻找改进候选项。

- **导航**：代理找到正确文件有多容易？文件间是否存在隐藏依赖？添加**导航指针**是否会更方便？*适用情况*：会话花了很长时间寻找某条信息。
- **自动检查**：是否有自动检查能够捕获代理犯的错误，例如 lint、类型检查、测试或文件系统检查器？先阅读仓库自己的检查命令，包括 `package.json` 或构建工具中的 `lint`、`check` 脚本和 CI 工作流。若已有检查未接入或悄悄失效，这本身就是发现，不要重新发明。仓库没有**防护机制**（既没有 pre-commit 钩子，也没有 CI 任务运行其 lint、typecheck、test 命令）本身也是发现：未接入 lint 的仓库意味着长期错失机会，而不是中性的默认状态。*适用情况*：代理的错误本可以被自动检查捕获，或者仓库完全没有防护机制。
- **编码规范**：是否应给**审查代理**增加一条要检查的规则？是否应删除或澄清现有规则？先对违规分类：**机械性**违规，例如固定语法模式、禁用 API、导入形式或文件位置规则，必须使用确定性检查。根据仓库语言和已有防护，选择成本最低的方式：仓库现有 linter 的自定义规则、新 pre-commit 钩子或新 CI 任务。默认应构建检查，而不是写一条文字规则。`CODING_STANDARDS.md` 应保留给真正的**判断性问题**，例如跨文件一致性、“符合周围风格”，以及任何防护机制都无法替代的判断。*适用情况*：审查代理漏掉了错误。
- **全局 AGENTS.md**：是否有引导指令更适合移到编码规范或自动检查中？*适用情况*：仓库级或用户全局的 AGENTS.md 特别庞大。
- **工具成本**：代理是否进行了可以简化的昂贵工具调用？是否有特别浪费 token 的自定义工具，例如 CLI 或 MCP？*适用情况*：代理进行了成本较高的工具调用。
- **无效指令**：寻找引导文件中不会改变代理行为的指令。*适用情况*：引导文件庞大难用。
- **信息获取**：寻找增加代理信息访问能力的机会，例如分流保存开发服务器日志、为第三方服务提供只读访问。*适用情况*：代理无法获得某项关键信息。

4. 按严重程度向用户呈现这些候选项。

## 参考

### 实现与审查

记住，所有工作都经过实现和审查两个阶段。实现代理承受最大的**上下文压力**，因为它负责探索、写代码和调试失败。

审查代理的上下文压力最小：它收到的是差异，不需要探索，通常也不需要写代码或调试。

因此，应由审查代理负责落实编码规范，而非实现代理。

### 文件

你可以使用仓库中的以下文件：

- `CLAUDE.md` / `AGENTS.md`：会被注入到在此仓库工作的任何代理的上下文窗口中。应极其克制地使用，通常只放指向其他文件的**导航指针**。
- `CODING_STANDARDS.md`：在审查阶段读取，而非实现阶段。超过 1,000 行时，添加指向文档目录的**导航指针**。
- 文档：用作文档参考，通过其他文件指向它们。写新文档前，先寻找现有文档。
- 技能：可以承载文档（描述会进入代理上下文窗口），也可以提供用户调用的命令。遵循 `writing-for-agents` 技能中的建议。
